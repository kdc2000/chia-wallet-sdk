## Tech Debt Aggregate

3 documented items, all pre-existing, all out-of-scope per the GSD executor scope-boundary rule. None block milestone closure.

1. **`chia-sdk-daemon/src/client.rs:426-427` clippy::pedantic warnings** — predate Phase 1 entirely (commit `ec1a3517`, 2026-04-19). CI clippy exits 0 because the workflow doesn't pass `-D warnings`. Documented in Phase 1 + Phase 6 deferred-items.md. **Recommended PR:** 2-line consolidation of the `tungstenite::Message::*` match arms; or add `-D warnings` to CI's clippy step to make the local + CI gates align.

2. **`chia-sdk-utils/src/silent_payments/mod.rs:40` rustdoc private-intra-doc-link warning** — Phase 3 reach-through wrapper. CI doesn't run `cargo doc`, so this only trips local stricter gates. Documented in Phase 4.2 deferred-items.md. **Recommended fix:** downgrade the intra-doc link to plain code or add `#[allow(rustdoc::private_intra_doc_links)]` on the wrapper.

3. **`SendDestination` `missing_copy_implementations` warn-level lint** in no-features builds — single-variant `PuzzleHash(Bytes32)` enum without chip-0057. Workspace policy is `warn`, not `deny`; builds exit 0. Documented in Phase 6 deferred-items.md. **Acceptable as-is** — the chip-0057 path adds `SilentPayment(Box<…>)` which is not Copy, so the lint correctly fires only in the trimmed-feature CI permutation.

## Risk Notes for v2

- **CAT2 send + receive** (deferred per PROJECT.md OOS). Receiver-side needs indexer-level layer-aware extraction; today CAT2 SP sends would produce undetectable payments.
- **CHIP-0058 transport client** (deferred). v1 ships `TweakData` as a transport-agnostic input type so adapters can plug in without breaking the SDK API.
- **`SilentPaymentTweakSource` async trait** (deferred with the transport client).
- **m=0 self-change machinery** — RESEARCH §3b disproved D-04's assumption that the SDK auto-emits self-change. If/when self-change is actually implemented, the m=0 e2e test will need to be re-redesigned to exercise the real path (the current test is a LabelRegistry-consistency guard).
- **Cargo cyclic-dev-dep type confusion** — Phase 6 Plan 06-03 had to inline `build_tweak_data` in driver-side tests because `chia_sdk_test::silent_payments::tweak_data_from_simulator_block` couldn't be directly called from chia-sdk-driver dev-deps. The canonical cross-crate path is still exercised by Plans 06-04 + 06-05. Not a v2 blocker, but worth tracking if cross-crate dev-dep ergonomics improve in rustc.
