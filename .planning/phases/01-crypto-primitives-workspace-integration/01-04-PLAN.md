```rust
//! BIP-32-style unhardened derivation paths for CHIP-0057 silent-payment
//! scan and spend keys.
//!
//! ```text
//! m/12381/8444/12/0   scan secret key  (b_scan)
//! m/12381/8444/13/0   spend secret key (b_spend)
//! ```
//!
//! Indices `12` (scan) and `13` (spend) are CHIP-0057 reserved values,
//! distinct from index `2` used by the standard Chia wallet.
//!
//! NOTE: All scalar reduction in CHIP-0057 code paths goes through
//! [`super::ScalarField`]. Do NOT introduce alternate reducers in this
//! module — in particular, the signed reducer used by the standard-puzzle
//! synthetic-key offset (in `chia_puzzle_types::derive_synthetic`) takes
//! a different sign interpretation and silently disagrees with
//! `from_bytes_unsigned` on inputs whose top bit is set.

/// Unhardened derivation path for the silent-payment scan secret key:
/// `m/12381/8444/12/0`.
pub const SCAN_PATH: &[u32] = &[12381, 8444, 12, 0];

/// Unhardened derivation path for the silent-payment spend secret key:
/// `m/12381/8444/13/0`.
pub const SPEND_PATH: &[u32] = &[12381, 8444, 13, 0];
```

Important constraints (also enforced by acceptance criteria):

- The two constants are `pub const &[u32]` (NOT `pub const [u32; 4]` or `&'static [u32; 4]`) — `&[u32]` matches what `chia_bls::DerivableKey::derive_unhardened` consumers iterate over in Phase 2.
- The four indices for SCAN_PATH MUST be in the order `[12381, 8444, 12, 0]` and for SPEND_PATH `[12381, 8444, 13, 0]`. Swapping any two breaks Phase 2's CHIP-test-vector address round-trip.
- The doc-comment uses descriptive phrasing only ("the signed reducer used by the standard-puzzle synthetic-key offset"). The literal function-name token MUST NOT appear anywhere in this file.

This file has no tests. Path values are validated end-to-end at Phase 2 (ADDR-01) when `SilentPaymentKeys::from_mnemonic` runs against the CHIP test vectors. Adding a `#[test]` here would tautologically assert `SCAN_PATH == [12381, 8444, 12, 0]` against itself.
