# Phase 04.1: Sage-style binding refactor — Phase Summary

**Phase 4.1 swaps the SP-specific opcode 60/61 empty-message announcement binding (Phase 4's `emit_silent_payment_announcements`) for the SDK's general-purpose `Relation::AssertConcurrent` cycle binding (opcode-64 SCC). Multi-input silent payment transactions now blend into the SDK's regular-traffic anonymity set — no SP-uniquely-identifiable marker remains on chain. A runtime gate (`DriverError::SilentPaymentRequiresInputBinding`) hard-errors `Relation != AssertConcurrent` on multi-input SP sends to prevent accidental degradation. The `Relation` enum gains rustdoc naming CHIP-0057 Pass 2b as load-bearing on `AssertConcurrent`; a parametric pinning test (N=2,3,4) guards against future emission-shape drift. All 7 ROADMAP §04.1 success criteria PASS; FINGERPRINT-01 (new) closes fully; SEND-06 re-validates under the new binding scheme. Workspace test count: 2416 → 2419 (net +3: 5 new − 2 deleted).**

## Key Decisions

1. **Cycle binding over SP-specific announcement.** Phase 4's opcode 60/61 empty-message announcement was uniquely identifiable as silent-payment traffic, eroding the SP anonymity set. The SDK's pre-existing `Relation::AssertConcurrent` cycle (opcode-64 closed cycle, used pervasively across the SDK for atomic multi-coin bundles) provides equivalent multi-input atomicity AND blends SP traffic into regular-SDK traffic. The receiver detects the SCC over opcode-64 references either way; the cycle topology (lex-min vs iteration-order) doesn't affect SCC computation.

2. **Runtime gate placement between Step 1 and Step 2.** The empty-pending short-circuit (Step 1) protects non-SP transactions from paying any gate cost. The XCH input collection (Step 2) does work the gate would render moot. Placing the gate between the two minimizes wasted work and keeps the conceptual separation clean. Implementation uses `iter().filter(|i| !i.ephemeral).count()` — separate from Step 2/3's loop (which has different filter conditions and needs the items in the iteration), at small constant overhead.

3. **Rustdoc and pinning test NOT cfg-gated on chip-0057.** `Relation` is general-purpose; SP is one consumer. Gating the rustdoc would hide it from non-chip-0057 consumers of the SDK who still need to understand `AssertConcurrent`'s atomic-binding semantics. Gating the pinning test would mean the cycle-emission shape could drift in chip-0057-disabled builds without triggering the test — defeating the purpose of pinning a general-purpose invariant. (RESEARCH §Pitfall D + §Pitfall F.)

4. **Two-plan slicing.** Plan 04.1-01 was deletions + test arg updates (~150 lines removed, ~5 edits). Plan 04.1-02 was additions (~255 lines added across 4 files). Splitting kept each plan's commit story clean and let Plan 04.1-01 land with a transient test-build break (documented in its SUMMARY) that Plan 04.1-02 closed atomically.

5. **Preempted Plan 04.1-02's gate in Plan 04.1-01's test updates.** Plan 04.1-01 updated `multi_party_hard_errors` and `input_hash_round_trip` to `Relation::AssertConcurrent` proactively, so Plan 04.1-02's gate addition was a no-op for them (no test regressions to chase after the gate landed). The two truly announcement-specific tests were deleted in 04.1-01 since they tested deleted infrastructure. (RESEARCH §Pitfall B handled preemptively.)

6. **Three named pinning tests (not rstest).** Three `#[test]` functions over N=2/3/4 (each calling `assert_concurrent_cycle_for_n(n)`) produce stable test names that match the VALIDATION.md grep pattern and give clean per-N failure messages. Rstest's parametric macros would also work but add a macro layer that complicates test-name grep matching.

7. **Inline-fixed lints/registration omissions; no `#[allow]`.** All 5 deviations across both plans were inline correctness fixes: clippy doc_markdown (Plan 04.1-02 Task 3 — backtick snake_case `coin_id`), broken intra-doc link (Plan 04.1-02 Task 3 — downgrade `[`...`]` to plain code), unused import (Plan 04.1-02 Task 3 — drop `Asset`), missing REQUIREMENTS.md entry for FINGERPRINT-01 (Plan 04.1-02 Task 4 — added entry + traceability), and a rustfmt auto-cleanup (Plan 04.1-02 Task 4 — collapse 4-line `apply()` call). Zero new `#[allow]` attributes; only the pre-existing Plan 03-03 `scanner.rs#[allow(clippy::similar_names)]` remains across SP trees.
