# Phase 9 Plan 4: Spends.prepare Option<Relation> binding extension Summary

**`Spends.prepare(deltas, relation: Option<Relation>)` now ships across all 3 binding targets (napi, wasm, pyo3); Python multi-input SP sends become reachable via `spends.prepare(deltas, Relation.assert_concurrent())`, with the existing single-input pyo3 E2E test passing unchanged (zero source edits) thanks to a bindy-macro pyo3 codegen patch that adds `arg=None` defaults for trailing-position `Option<T>` parameters.**

## Decisions Made

- **Patch bindy-macro rather than edit existing tests** (key decision driving the entire deviation). The plan explicitly listed editing the pyo3 test as a LAST RESORT graceful degradation; the hard regression bar in CONTEXT.md acceptance forbids signature changes beyond the optional `Relation` parameter on existing pyo3 callers. The root-cause fix is bindy-macro's missing pyo3 default-arg emission for `Option<T>` params — a one-block patch in pyo3 codegen, well-scoped, benefits every future trailing-Option binding.
- **Trailing-only default emission** in the bindy-macro patch. pyo3 rejects "required positional after optional" at macro-expansion time; the existing descriptor has middle-position Options (e.g., `Action.issue_cat.hidden_puzzle_hash`) that must keep their required positional shape. The patch computes the trailing-Option run boundary and emits `=None` defaults only for that suffix.
- **Use raw descriptor type for Option<T> detection** (`v.trim_start().starts_with("Option<")`, before `apply_mappings` rewrite). Mirrors the napi/wasm codegen pattern in the same file; avoids depending on mapping-flavor-specific rewrites.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing Critical Functionality] bindy-macro pyo3 codegen missing trailing-`Option<T>` default-arg emission**
- **Found during:** Task 2 verification step 5 (`cd pyo3 && python -m pytest tests/test_silent_payments.py::test_unlabeled_e2e -v` initially failed with `TypeError: Spends.prepare() missing 1 required positional argument: 'relation'`).
- **Issue:** The plan anticipated this case (RESEARCH Pitfall 5 + Open Q1: "bindy default-arg generation per target may differ"). The bindy-macro `bindy_pyo3!` codegen at `crates/chia-sdk-bindings/bindy-macro/src/lib.rs:~1216` emits `#[pyo3(signature = (#(#arg_idents),*))]` — a flat positional list with no defaults. pyo3 marshals every arg in that list as required positional, so `Option<T>` trailing args break ergonomic 1-arg call shapes. napi and wasm codegen already handle this natively (each generates `relation?: Relation | undefined`), so this is a pyo3-only gap.
- **Fix:** Added 23-line patch to the pyo3 codegen block: (a) compute `arg_is_optional: Vec<bool>` from the raw descriptor type string (`v.trim_start().starts_with("Option<")`); (b) compute trailing-only boundary via reverse iteration; (c) emit `quote!(#ident = None)` for trailing Options and `quote!(#ident)` otherwise. Substituted the `signature_args` vec into the existing `#[pyo3(signature = (#(#signature_args),*))]` quote. Trailing-only restriction preserves pyo3's "no required positional after optional" invariant for middle-Option descriptors (`Action.issue_cat.hidden_puzzle_hash` is the existing example).
- **Files modified:** `crates/chia-sdk-bindings/bindy-macro/src/lib.rs` (+23/-2 lines in the `bindy_pyo3!` method-codegen block).
- **Verification:** First failing attempt (apply default to ALL Options) caught by pyo3 macro-expansion error: "cannot have required positional parameter after an optional parameter" — confirmed the trailing-only restriction was needed. Second attempt (trailing-only) compiles cleanly; `test_unlabeled_e2e` passes; full pyo3 suite 2/2 passes; full napi suite 52/52 passes (no napi codegen change, so no impact); full wasm suite 8/8 passes (no wasm codegen change).
- **Committed in:** `2a654025` (Task 2 commit) — bundled with the action_system.rs and JSON descriptor edits because they're all needed together to make the pyo3 test pass.
