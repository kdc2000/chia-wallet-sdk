## Decisions Made

**None beyond plan spec.** The plan locked the camelCase exposure name (`SilentPayments.tweakDataFromBlockSpends`), the descriptor shape, and the delegation pattern. Three Claude's-discretion choices fell out cleanly:

1. **Method naming.** Bindy auto-derives camelCase: snake_case Rust `tweak_data_from_block_spends` → camelCase TS `tweakDataFromBlockSpends`. Generated `.d.ts` line 2821 confirms.
2. **Pyo3 `.pyi` path.** Not regenerated this plan — `pyo3` stubs ship via `cargo run -p pyo3-stub-generator` and are gated on `python3 -m maturin develop` having been run. Plan 09-06 (which adds the `pyo3/tests/test_silent_payments.py::test_multi_input_e2e` round-trip) is the natural trigger for the stub regeneration. The Python-side method is callable today via the bindy-macro registration; the `.pyi` lag affects IDE autocomplete only, not runtime callability.
3. **No new `#[allow]` attributes.** `cargo clippy -p chia-sdk-bindings --all-features --all-targets -- -D warnings` exits 0 unchanged; the only `#[allow]` anywhere in the SP-touched chia-sdk-bindings surface remains the long-standing scanner.rs allow inherited from plan 03-03 (not touched this plan).
