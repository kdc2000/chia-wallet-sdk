## Accomplishments

- `Action::send(id: Id, destination: impl Into<SendDestination>, amount: u64, memos: Memos)` is now the unified send constructor. All 16 SDK callers passing `Bytes32` literals + the bindings facade caller at `chia-sdk-bindings/src/action_system.rs:294` compile unchanged via the always-on `From<Bytes32> for SendDestination` bridge.
- `SendAction.destination: SendDestination` replaces `puzzle_hash: Bytes32`; `SendAction` loses `Copy` (SendDestination is `Clone`-only because Plan 04.2-01 boxed the chip-0057 variant).
- `SendAction::spend` gains a chip-0057 SP arm at the top of the body: `SilentPaymentRequiresXch` (Id check) fires first, then `memo_hint_guard` runs (relocated from `actions/silent_payment_send.rs`), then `spend_silent_payment` helper reserves an XCH parent via `output_source(BURN_PUZZLE_HASH, amount)`, increments the per-`scan_pk` k counter, and pushes a `SilentPaymentPending` entry. No `CreateCoin` is emitted at apply (deferred to finish).
- `Spends::finish_with_keys` gains a chip-0057 SP branch placed BEFORE `prepare()` (via private free fn `sp_finish_branch`) that short-circuits if `silent_payments_pending` is empty, fires `SilentPaymentRequiresInputBinding` (04.1 D-06 preserve) for ≥2 non-ephemeral XCH inputs with `Relation != AssertConcurrent`, fires `SilentPaymentKeysNotRegistered` if `silent_payment_synthetic_sks.is_none()`, runs the existing 9-step derivation pipeline (aggregate, recover PK, compute input_hash, per-pending derive + push CreateCoin via `create_coin_with_assertion`).
- The 3 tests in `silent_payments/send_keys.rs::tests` (`multi_party_hard_errors`, `multi_input_requires_assert_concurrent_relation`, `single_input_accepts_relation_none`) are reshaped to use `Action::send(Id::Xch, SendDestination::SilentPayment(Box::new(addr)), ...)` + `spends.with_silent_payment_keys(pk_map.clone(), sk_map)` + `spends.finish_with_keys(...)`. All 3 still pass with identical error variant semantics; they now exercise `with_silent_payment_keys` and the new `sp_finish_branch`, killing the dead_code-deny window that Plan 04.2-01 anticipated (but never actually surfaced — Plan 01's `prepare()` field-passthrough satisfied dead_code on its own).
- All 8 OLD tests in `actions/silent_payment_send.rs::tests` continue to pass against the unchanged OLD `Action::silent_payment_send` constructor + `Spends::finish_with_silent_payment_keys` method. Plan 04.2-03 will atomically delete both the OLD code and those 8 tests.

## Decisions Made

- **`Action::send`'s second parameter widened to `impl Into<SendDestination>` (NOT a literal `SendDestination`).** This is the must-have invariant from RESEARCH.md Pitfall 2 — keeps all 16 SDK and 12 Sage `Bytes32`-passing callers source-compatible. Confirmed by `test_action_send_xch` + `test_action_send_xch_with_change` + `test_action_send_xch_split` + 5 CAT variants (8 tests total in actions/send.rs::tests) passing unchanged.
- **`SendAction` drops `Copy`** (RESEARCH.md Pitfall 4). `SendDestination` is `Clone`-only because of the boxed `SilentPaymentAddress` variant from Plan 04.2-01. No in-crate consumer relied on `SendAction: Copy` — verified by clean workspace build.
- **`sp_finish_branch` is a private free fn**, not a method on `Spends`. The plan suggested it be in the same impl block as `with_silent_payment_keys`, but a free fn with `&mut Spends` is more flexible (no `Self` ambiguity; supports future extraction). Functionally equivalent.
- **`finish_with_keys` now takes `mut self`** (was `self`). The chip-0057 branch calls `sp_finish_branch(ctx, &mut self, relation)` which performs `mem::take` on `silent_payments_pending`. Under the no-features build the `mut` is unused; `cfg_attr(not(feature = "chip-0057"), allow(unused_mut))` is the precise scope of the allow (1 line, not function-level).
- **Gate ordering inside `sp_finish_branch` (Pitfall 7):** SilentPaymentRequiresInputBinding (04.1 D-06 preserve, line 574 in rustdoc / first runtime check) → SilentPaymentKeysNotRegistered (NEW, line 576 in rustdoc / second runtime check) → SilentPaymentMultiPartyUnsupported (existing SK-coverage) → SilentPaymentNoXchInputs. The 04.1 gate fires first because multi-input atomic binding is more fundamental than key registration; the test `multi_input_requires_assert_concurrent_relation` registers keys before triggering the gate and confirms the ordering at runtime.
- **Memo type in helper signatures uses `Memos` (default `<NodePtr>`)**, not the explicit `Memos<NodePtr>` form (RESEARCH.md Pitfall 5). Identical type at the type-checker level; matches `SendAction.memos: Memos` for type-inference cleanliness.
- **Test rewrite uses `SendDestination::SilentPayment(Box::new(recipient.clone()))`** because Plan 04.2-01 boxed the chip-0057 variant. The plan's BEFORE/AFTER recipe in RESEARCH.md was written before the boxing decision; the executor applied the obvious Box::new wrap.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 — Bug] Disambiguate three `.into()` call sites that Action::send's new `impl Into<SendDestination>` made ambiguous**
- **Found during:** Task 1 (cargo build -p chia-sdk-driver -F chip-0057 --all-targets)
- **Issue:** Three test sites passed `SETTLEMENT_PAYMENT_HASH.into()` (where `SETTLEMENT_PAYMENT_HASH: [u8; 32]`) as the second `Action::send` argument. Before this plan, `Action::send`'s second parameter was `Bytes32` (concrete type), so `[u8; 32]::into::<Bytes32>` resolved unambiguously. With the new `impl Into<SendDestination>` parameter, the `.into()` cannot decide between `[u8; 32] → Bytes32 → SendDestination` and a hypothetical direct `[u8; 32] → T` for the bound's `T` — clippy raises E0283 (type annotations needed).
- **Fix:** Updated each site to `Bytes32::new(SETTLEMENT_PAYMENT_HASH)` (explicit Bytes32 constructor that takes `[u8; 32]`). This eliminates the ambiguity by producing a concrete `Bytes32` which then trivially coerces through `From<Bytes32> for SendDestination`.
- **Files modified:** `crates/chia-sdk-driver/src/actions/settle.rs`, `crates/chia-sdk-driver/src/clear_signing.rs`, `crates/chia-sdk-driver/src/offers/offer.rs`
- **Verification:** `cargo build -p chia-sdk-driver -F chip-0057 --all-targets` exits 0 with zero errors. All driver tests (2330) pass.
- **Committed in:** `08411089` (Task 1 commit)
