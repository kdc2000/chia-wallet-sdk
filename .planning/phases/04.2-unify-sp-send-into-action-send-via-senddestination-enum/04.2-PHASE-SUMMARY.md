# Phase 04.2: Unify SP send into Action::send via SendDestination enum — Phase Summary

**Phase 04.2 folds the dedicated `Action::SilentPaymentSend` variant + `Action::silent_payment_send` constructor + `Spends::finish_with_silent_payment_keys` finish overload + 640-line `actions/silent_payment_send.rs` file into the generic `Action::send` + `Spends::finish_with_keys` surface. Silent-payment becomes a destination type (`SendDestination::SilentPayment(Box<SilentPaymentAddress>)`), not a separate action variant. `impl From<Bytes32> for SendDestination` keeps all 28 existing `Action::send(id, ph, amount, memos)` callers (12 in Sage, 16 in SDK + 1 bindings facade) compiling unchanged. SP keys move onto `Spends` via the new `with_silent_payment_keys(pks, sks)` chainable builder; the chip-0057 SP derivation pipeline absorbs into `Spends::finish_with_keys` via a private `sp_finish_branch` helper. Matches Sage's existing single-`Action::send`-call-shape model where every wallet operation (XCH/CAT/DID/NFT/option/multi-send/offers) goes through one constructor. All 13 ROADMAP §04.2 success criteria PASS; SEND-04 re-validates under the new construction shape; ACTION-API-01 newly closes. Workspace test count: 2419 → 2421 (+2 NEW Wave 0 acceptance tests).**

## Key Decisions Taken

1. **SendDestination location: `action_system/send_destination.rs`** (Plan 01). Concept-grouped with `id.rs`, `relation.rs`. Precedent for future Action constructor target discriminators.
2. **SendDestination::SilentPayment variant boxed** (Plan 01 deviation). `clippy::large_enum_variant` fires on the bare variant because `SilentPaymentAddress` is ~296 bytes; the always-on `PuzzleHash(Bytes32)` is 32 bytes. Boxed inline; `Clone` preserved through `Box: Clone`; the type contract is semantically equivalent.
3. **`Action::send` widened to `impl Into<SendDestination>`** (Plan 02). The must-have invariant from RESEARCH.md Pitfall 2: keeps all 16 SDK + 12 Sage + 1 bindings-facade `Bytes32`-passing caller source-compatible via `From<Bytes32>`.
4. **`SendAction` drops `Copy`** (Plan 02 RESEARCH.md Pitfall 4). `SendDestination` is `Clone`-only because of the boxed `SilentPaymentAddress` variant. No in-crate consumer depended on `SendAction: Copy`.
5. **`sp_finish_branch` is a private free fn** (Plan 02). Outside `impl Spends<Unfinished>`, taking `&mut Spends`. More flexible than a method (no `Self` ambiguity; supports future extraction).
6. **Atomic Wave B single-commit deletion** (Plan 03). Tasks 1+2 combined into commit `4cd99543` per RESEARCH.md §"Atomic Commit Sequencing" Wave B — the deletions are interdependent (variant + module + re-exports + dispatch + tests all reference each other; transient broken states avoidable).
7. **Test homing: `actions/send.rs::silent_payment_tests`** (Plan 03). One chip-0057-cfg-gated sibling sub-module, all 10 tests together (8 relocated + 2 NEW Wave 0). Close to the relocated apply-time SP arm + `memo_hint_guard` + `spend_silent_payment` helpers. Cohesion-focused over alternative split into two destination files.
8. **Zero new `#[allow]` streak preserved** across Phase 04.2 (continues Plan 04-03 / Plan 04-05 / Plan 04.1 precedent). All inline lint fixes are real renames, structure changes, or downgrades — never suppressions.
9. **Privacy-warning rustdoc prefix normalization** (Plan 03). `"Privacy warning (chip-0057):"` → `"Privacy warning: under chip-0057,"` so the strict SEND-08 grep gate (`"Privacy warning:"`) counts the entry. Final count: 10.
10. **Pre-existing chia-sdk-utils rustdoc error deferred** (Plan 03 deviation 4). `generate_label` reach-through wrapper at `chia-sdk-utils/src/silent_payments/mod.rs:40` has a broken intra-doc link to a `pub(crate)` item (Plan 03-04 origin). Verified pre-existing on `main`. Out of Phase 04.2 scope (no chia-sdk-utils touches). Logged to `deferred-items.md` for a Phase 5 or maintenance plan.
