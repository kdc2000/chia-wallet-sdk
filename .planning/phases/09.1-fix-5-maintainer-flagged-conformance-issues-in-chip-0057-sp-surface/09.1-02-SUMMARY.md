## Accomplishments
- Closed ISSUE-1: the FFI-reachable `SilentPayments::compute_input_hash` facade guards an empty `coin_ids` list and returns a typed `Err` before delegating to the driver fn, so a Python/JS/WASM caller passing an empty list gets a typed error instead of aborting the host process.

## Decisions Made
- **FACADE-GUARD over signature change:** Guarding the one FFI-reachable facade is strictly lower-churn than changing the driver fn's signature (which would touch all 5 call sites + ~8 tests). The two production callers already pass non-empty slices, so the internal invariant stands and only the FFI seam needed a guard.
- **Reused `DriverError::SilentPaymentNoXchInputs`:** The existing variant already carries the exact semantics ("silent payment requires at least one wallet-controlled XCH input"); `bindy::Error::Driver(#[from] DriverError)` converts it cleanly via `.into()`. No new error variant.
- **Tested under default + wasm features (not `--all-features`):** `--all-features` activates the napi backend, whose `Error` drop glue references Node host-runtime symbols (`napi_reference_unref`, `napi_delete_reference`) that cannot link a standalone Rust test binary outside a Node addon context. The SP facade is not `chip-0057`-gated and not feature-specific, so the empty-input and single-input tests exercise byte-identical code under any binding feature — both pass under default and under `--features wasm`.

The SP facade is not feature-gated, so these run the exact code path the FFI bindings call. The napi-specific code path is independently covered by the napi AVA suite in prior phases.

**2. [Rule 1 - Bug] `unwrap_err()` requires `Debug` on the `Ok` payload, which `ScalarField` does not derive**
- **Found during:** Task 2 (first test compile)
- **Issue:** The boundary test originally used `result.unwrap_err()`, which requires `T: Debug` on the `Result<T, E>` `Ok` type. The facade `ScalarField` wrapper does not derive `Debug` (and adding the derive would be out-of-scope churn on a production type).
- **Fix:** Restructured the assertion to `let Err(err) = &result else { panic!(...) }`, matching on a reference so no `Debug` bound on the `Ok` payload is required. Variant + display-string assertions unchanged.
- **Files modified:** `crates/chia-sdk-bindings/src/silent_payments.rs`
- **Verification:** test compiles and passes; no `Debug` derive added to any production type.
