## Accomplishments
- `SyntheticSecretKey` / `SyntheticPublicKey` newtypes wrap `chia_bls::{SecretKey, PublicKey}` with `from_raw` (synthesizes via the default-hidden `DeriveSynthetic` path — byte-identical to `puzzle_hash_for_pk`), `from_synthetic_unchecked` (bit-preserving escape hatch), `public_key`, `into_inner`, `as_inner`. `Copy` derived only on the PublicKey newtype.
- `Spends::with_silent_payment_keys` signature changed to take the newtype maps; storage fields stay plain `chia_bls` types, unwrapped via `.into_inner()` at the boundary — so passing a raw `chia_bls::PublicKey`/`SecretKey` no longer type-checks (E0308). The compile-error proof is empirically witnessed by the binding facade requiring an explicit newtype wrap to keep compiling.
- All 8 in-repo Rust call sites updated via `from_synthetic_unchecked` (2 example + 3 e2e + 3 unit), the `&pk_map` passed to `finish_with_keys` kept as the raw `IndexMap<Bytes32, PublicKey>`. The 3 e2e oracle tests pass byte-identically (no detection-oracle regression).
- The inaccurate "`finish_with_keys` ... is the prevention mechanism" comment in `protocol.rs` corrected to describe the actual GUARD-02 (compile-time newtype) + GUARD-01 (finish-time runtime guard) layered defense; the presence/coverage gates are explicitly noted NOT to validate synthetic-ness.
- Newtypes re-exported from `chia_sdk_driver::silent_payments` and the umbrella prelude (both chip-0057 gated). Resolves the long-deferred STATE Q2.

## Decisions Made
- **Storage stays plain, newtype guards the boundary.** Kept `silent_payment_synthetic_pks/_sks` as `Option<IndexMap<Bytes32, PublicKey/SecretKey>>` and unwrapped via `.into_inner()` inside `with_silent_payment_keys` — zero blast radius into `sp_finish_branch`, the `Finished`-state move, or `finish_with_keys`.
- **All callers use `from_synthetic_unchecked`, not `from_raw`.** The `sim.bls()` fixtures curry over the RAW pk, so the registered key already equals the would-be-synthetic key for those coins; `from_raw` would double-synthesize and break byte-equality with the coin's puzzle hash. (Wallets sending from real standard-spend coins use `from_raw`.)
- **Binding facade wrapped via `from_synthetic_unchecked`.** Byte-identical to the prior verbatim behavior, so no binding test regresses; the GUARD-03 raw-key entry point (internal `from_raw` synthesis) is Plan 03's scope.
