# Phase 09.2 Plan 03: Raw-key silent-payment bindings (GUARD-03) Summary

**Every FFI target's `with_silent_payment_keys` now accepts RAW `PublicKey`/`SecretKey` and synthesizes the synthetic key internally via `from_raw` (= `derive_synthetic`, default hidden) — closing GUARD-03 so no silent failure remains in any language surface; the raw-key happy path detects a coin in napi/pyo3/wasm and a wrong key surfaces the typed `SilentPaymentKeyNotSynthetic` error across the FFI boundary (GUARD-01 backstop, single-input proven in each target).**

## Accomplishments
- `Spends::with_silent_payment_keys` binding facade rewritten: each registered entry is now wrapped via `SyntheticPublicKey::from_raw(&entry.public_key)` / `SyntheticSecretKey::from_raw(&entry.secret_key)` (was `from_synthetic_unchecked` — the Plan-01 temporary bridge). This both fixes raw-key ergonomics for FFI callers and delivers GUARD-03's "synthesize internally."
- Method rustdoc rewritten to state the facade accepts RAW keys and synthesizes via the default hidden puzzle; documents the default-hidden assumption and that a custom-hidden coin fails LOUD with `DriverError::SilentPaymentKeyNotSynthetic` at finish (GUARD-01), never silently — the escape hatch (`from_synthetic_unchecked`) is Rust-only.
- Wrapper struct docs (`SilentPaymentRegisteredKey` / `SilentPaymentRegisteredSecretKey`) updated to say `raw public_key` / `raw secret_key` with the facade-synthesizes-internally note. Struct + field names kept (no descriptor / test churn).
- Descriptor verified driftless — arg TYPES unchanged because the wrapper struct names stay; `bindings/action_system.json` needed no edit; `scripts/sp_descriptor_facade_drift.sh` reports zero drift (23 methods both sides).
- All three binding suites green: napi 54, wasm 10, pyo3 4. Each happy-path e2e now builds a synthetic-keyed coin so a raw-key registration detects; each file has a single-input negative test asserting `SilentPaymentKeyNotSynthetic` crosses the FFI boundary with no bundle produced.

## Decisions Made
- **Facade uses `from_raw`, descriptor unchanged.** The wrapper struct names and field names (`public_key`/`secret_key`) remain accurate as raw keys, so the only Rust change is the wrap-via-`from_raw` and the rustdoc; the JSON descriptor and all three test-file imports of the wrapper classes stay stable. Drift script confirms zero drift.
- **Happy-path coins live at the synthetic puzzle hash.** Required because (a) `sim.bls()` curries over the RAW pk and (b) the simulator's `sign_transaction` keys by `sk.public_key()` with no synthetic derivation. So the coin is built at `curry_tree_hash(derive_synthetic(pk))`, spent via `standardSpend(pk.deriveSynthetic())`, and signed with `sk.deriveSynthetic()`.
- **Negative test reuses the raw-curried `sim.bls()` coin.** Registering RAW `pk`/`sk` makes the facade synthesize `derive_synthetic(pk)` whose `curry_tree_hash != sim.bls() puzzleHash`, so GUARD-01 fires inside `prepare()`. Single-input case — proves the guard fires across FFI for one input in each target.
