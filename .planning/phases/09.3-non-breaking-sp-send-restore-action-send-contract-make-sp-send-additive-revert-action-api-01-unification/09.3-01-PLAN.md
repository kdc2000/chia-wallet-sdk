<objective>
Restore the pre-Phase-4.2 `Action::send` / `SendAction` public contract byte-for-byte, and make CHIP-0057 silent-payment send a separate `chip-0057`-gated `Action::SilentPaymentSend` variant + `Action::silent_payment_send` constructor. Delete `SendDestination` from `chia-sdk-driver` entirely.

Purpose: Phase 4.2 folded SP send into `Action::send(id, impl Into<SendDestination>, ...)`. That `impl Into` source-breaks downstream consumers (Sage: `E0283` on `.into()` call sites, `E0560` on `SendAction { puzzle_hash }` struct literals). This plan reverts the generic send contract to a concrete `Bytes32` parameter and makes SP additive-behind-flag, with zero blast radius on the non-gated `send`.

Output: A workspace that builds with `chip-0057` ON and OFF; `Action::send` takes a concrete `Bytes32`; SP send only via `Action::silent_payment_send`; the SP detection oracle (one-time puzzle hash derivation) unchanged.

THIS IS A FORWARD HAND-EDIT, NOT A git revert. Phases 5-9.2 rewrote the same files; a revert would conflict on every hunk and delete the GUARD-01/02/03 work. Use `git show 5bbb54bc^:<path>` ONLY as a byte-exact template for the CONTRACT shapes.

GUARD PRESERVATION (do NOT touch): GUARD-01 (runtime guard in `sp_finish_branch` in spends.rs), GUARD-02 (`SyntheticPublicKey`/`SyntheticSecretKey` newtypes in silent_payments/send_keys.rs + `with_silent_payment_keys`), GUARD-03 (raw-key bindings, not in this plan). The finish path (`sp_finish_branch` -> `derive_one_time_puzzle_hash`) reads `silent_payments_pending` + synthetic-key maps — never `SendDestination`/`SendAction` — so relocating the apply-time record verbatim keeps the one-time PH byte-identical.
</objective>
