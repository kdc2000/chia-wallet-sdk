# Phase 09.3: Non-breaking SP send (Plan 01 — Rust core) Summary

**Restored the pre-Phase-4.2 `Action::send(Bytes32)` / `SendAction{puzzle_hash}`+`Copy` public contract byte-for-byte and relocated CHIP-0057 silent-payment send into a separate `chip-0057`-gated `Action::SilentPaymentSend` variant + `Action::silent_payment_send` constructor — deleting `SendDestination` and the now-unreachable `SilentPaymentRequiresXch` — with the detection oracle (one-time puzzle-hash derivation) byte-identical.**

## Accomplishments

- `Action::send` is concrete `Bytes32` again (no `impl Into<SendDestination>`) → eliminates the `E0283` ambiguity at `.into()` call sites. `SendAction` regained its `puzzle_hash: Bytes32` field and `Copy` derive → eliminates the `E0560` struct-literal break.
- SP send is now reachable only via `Action::silent_payment_send(recipient, amount, memos)`, a `chip-0057`-gated variant with two internal dispatch arms. With `chip-0057` OFF the variant/ctor/arms vanish and the 11-arm match stays exhaustive.
- `SendDestination` removed from the driver (0 references); `DriverError::SilentPaymentRequiresXch` removed (structurally unreachable in an XCH-only action).
- Apply-time SP logic relocated verbatim, preserving the recorded `SilentPaymentPending` and thus the one-time puzzle hash.
