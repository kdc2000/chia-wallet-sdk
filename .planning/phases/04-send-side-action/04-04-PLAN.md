Wave 4 of Phase 4: layer the multi-input handling (k-counter behaviour at the test level + opcode 60/61 announcement binding at the implementation level) on top of Plan 04-03's working finish-time flow. After this plan:

- **k-counter coordination (SEND-05):** Two `SilentPaymentSend` actions to the same `scan_pk` in one `Spends::apply` call produce outputs at `k=0` and `k=1` respectively. The counter increment was already implemented in Plan 04-02's action code (`spends.silent_payment_counters.entry(scan_pk_bytes).or_insert(0); let k = *next_k; *next_k += 1;`); this plan adds the integration tests proving the behaviour.

- **Cross-input announcement binding (SEND-06):** Multi-input sends across different wallet key indices emit `CREATE_COIN_ANNOUNCEMENT` (opcode 60) on the lex-min coin and `ASSERT_COIN_ANNOUNCEMENT` (opcode 61) on every other XCH input, with `message = b""`. This allows the recipient's Pass 2b scanner to group the inputs and reconstruct the same `input_hash` the sender used. Without this, cross-index sends are undetectable.

ROADMAP Phase 4 success criteria #3 (k-counter) and #4 (announcement binding) close after this plan.

Implementation strategy:
1. Add an internal `emit_silent_payment_announcements` helper to `silent_payments/send_keys.rs` (private — `pub(crate)` is fine, no public API).
2. Insert one call to the helper into `finish_with_silent_payment_keys` between step 8 (CreateCoin emission) and step 9 (`finish_with_keys` delegation).
3. Add 5 new integration tests covering all four SEND-05/06 behaviours (k=0 then k=1; independent counters per scan_pk; no announcement on single-input; lex-min selection on multi-input; input_hash round-trip).

The Python reference (`~/silent-payments/send_payment.py:303-323`) is canonical for the wire format. The lex-min coin_id selection (vs. Python's iteration-order announcer choice) is the SDK's deliberate choice for order-independence — `04-RESEARCH.md §5c` documents the tradeoff. Inside the same `impl Spends { ... }` block (or a new one — both compile), add the `pub(crate)` method. Put it BEFORE `finish_with_silent_payment_keys` so the call site `self.emit_silent_payment_announcements(...)` is forward-defined:

```rust
impl Spends {
    /// Emit cross-input announcement binding (opcode 60/61) for ≥2-input
    /// silent-payment sends.
    ///
    /// Algorithm (per CHIP-0057 §319-329 + `04-RESEARCH.md` §5):
    /// - If `xch_input_ids.len() < 2`, return Ok(()) immediately (no binding
    ///   needed for single-input scenarios — the receiver's Pass 2b only
    ///   needs linkage to GROUP inputs).
    /// - Otherwise select `lex_min_coin_id = xch_input_ids.iter().min()`. On
    ///   that coin emit `CREATE_COIN_ANNOUNCEMENT` (opcode 60) with
    ///   `message = b""`. On every OTHER non-ephemeral XCH input emit
    ///   `ASSERT_COIN_ANNOUNCEMENT` (opcode 61) with `announcement_id =
    ///   SHA256(lex_min_coin_id || b"")`.
    ///
    /// Lex-min vs Python-reference iteration-order: `04-RESEARCH.md` §5c
    /// documents the tradeoff. Lex-min is order-independent — the SDK's
    /// `Spends` builder pattern lets coin insertion order vary, so a
    /// deterministic choice is required. Receiver-side Pass 2b doesn't
    /// care which input is the announcer; both choices produce identical
    /// detection.
    ///
    /// Method-on-`Spends` shape (not a free function over `&mut
    /// FungibleSpends<Coin>`): Plan 04-04 Task 2's tests need to call this
    /// independently of `finish_with_silent_payment_keys` (which consumes
    /// `self`) to inspect conditions on `self.xch.items` after the binding
    /// is emitted but before finish runs.
    pub(crate) fn emit_silent_payment_announcements(
        &mut self,
        _ctx: &mut SpendContext,
        xch_input_ids: &[Bytes32],
    ) -> Result<(), DriverError> {
        if xch_input_ids.len() < 2 {
            return Ok(());
        }

        let lex_min_coin_id = *xch_input_ids
            .iter()
            .min()
            .expect("non-empty checked above");

        let empty_message: Bytes = Bytes::new(vec![]);
        let ann_id = announcement_id(lex_min_coin_id, &empty_message);

        for item in self.xch.items.iter_mut() {
            if item.ephemeral {
                continue;
            }
            let coin_id = item.asset.coin_id();
            let SpendKind::Conditions(spend) = &mut item.kind else {
                continue;
            };
            if coin_id == lex_min_coin_id {
                spend.add_conditions(
                    Conditions::new().create_coin_announcement(Bytes::new(vec![])),
                );
            } else {
                spend.add_conditions(Conditions::new().assert_coin_announcement(ann_id));
            }
        }
        Ok(())
    }
}
```
