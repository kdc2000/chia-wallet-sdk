<objective>
Fix the CHIP-0057 multi-input silent-payment detection false-negative that occurs when an SP send is co-bundled with a non-XCH asset (CAT/DID/NFT). Add a mixed-asset multi-input round-trip regression test.

Purpose: Today the send side computes two coin sets independently. The input-hash set `S` is the non-ephemeral XCH inputs only, but the `AssertConcurrent` binding cycle (`C`) emitted by `emit_relation` runs over ALL conditions-spends (XCH + CATs + DIDs + NFTs). When a non-XCH coin is in the bundle, the cycle threads through it (e.g. `X1 -> CAT -> X2 -> X1`). The receiver (`tweak_data_from_block_spends`) reconstructs spend groups as strongly-connected components over STANDARD-PUZZLE spends only — the CAT node is dropped at Stage 1, the surviving XCH edges (`X2 -> X1` only) no longer form a cycle, no size>=2 SCC is produced, and the sender's `input_hash` over `{X1, X2}` is never reproduced. The SP payment lands at the correct one-time puzzle hash (funds are safe) but the standard scanner silently fails to detect it. XCH-only bundles are unaffected (`C == S` there) and ALL existing tests cover only that case.

Output: An SP-specific closed XCH-only `AssertConcurrentSpend` cycle emitted inside the chip-0057 finish path over exactly the input set fed to `compute_input_hash`, plus a failing-before/passing-after regression test driving the real send path.
</objective>
