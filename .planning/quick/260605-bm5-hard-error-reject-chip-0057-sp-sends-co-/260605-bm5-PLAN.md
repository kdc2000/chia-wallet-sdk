<objective>
Reverse the policy set by quick task 260605-av7. That task made multi-input SP sends co-bundled with non-XCH assets (CAT/DID/NFT/option) DETECTABLE by emitting an extra XCH-only `AssertConcurrentSpend` sub-cycle in `sp_finish_branch`. The user now wants such bundles REJECTED instead.

Enforce the invariant: **silent-payment send bundles are XCH-only.** When an SP payment is pending and the bundle contains any non-XCH asset spend, `Spends::finish_with_keys` must hard-error with a new `DriverError::SilentPaymentMixedAssetBundle`.

Purpose: A simpler, safer contract — mixed-asset SP bundles are unsupported and fail loudly rather than relying on a delicate sub-cycle to remain detectable.
Output: New error variant, an early uniform guard in `sp_finish_branch`, a possible deletion of the av7 sub-cycle (gated on the CAVEAT verification below), and a rejection test replacing the av7 detection test.
</objective>

   fn test_simulator_e2e_multi_input_mixed_asset_rejected() -> Result<()> {
       let mut sim = Simulator::new();

       let a = sim.bls(600);
       let b = sim.bls(600);
       let mnemonic = Mnemonic::parse(TV1_MNEMONIC)?;
